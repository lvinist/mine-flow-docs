## 5. Known follow-ups

- **Android E2E is now verified — the deferral is cleared.** The emulator's
  network was never actually gone: `ping 8.8.8.8` was 100% loss because **only
  ICMP was blocked** — TCP/443 worked end-to-end (an `nc` + `http` probe to the
  Supabase host returned a live upstream `HTTP/1.1 400`), so journey HTTPS
  traffic was fine and the round-g login failures were a red herring from an
  emulator that had since been cold-booted. All 6 Android journeys pass at
  `cb9d510` (guard exit 0 each): land_clearing, reporting, attendance,
  benchmark, inventory, cut_fill.
- **Attendance edit-flow read-back — resolved as part of the Android pass.**
  The journey's final list assertion was guarded *invertedly*: it scrolled only
  when the saved remark row was already built, but a `SliverList` builds only
  visible children, so the scroll was skipped exactly when the row was below
  the fold. Web passed because the list fit the viewport; Android's smaller
  viewport did not, and the assertion missed a record the repository had
  already persisted (step 7 passed). The guard now keys on the scrollable, and
  `scrollUntilVisible` is what materializes the row. `cb9d510`.
- **CI artifacts not fetched.** GitHub artifact downloads for the failing CI
  run at the pre-batch head (`34997516022`; web artifact `10409870215`, android
  `10408544929`) require credentials not present in this session. The local web
  re-runs in §4 supersede them for evidence purposes.
- **Attendance edit-flow read-back.** The journey's edit leg (sick → leave)
  asserts on the repository, not the refreshed list, because the list reload is
  async; a future pass could assert the rendered row once the reload settles.
- **Sync-queue emit shape.** ATT-02's fix guards the listener; a deeper fix
  would clear `successMessage` after the first consumption so downstream
  listeners cannot re-fire on queue churn. Recorded as a STEP-56 candidate.
