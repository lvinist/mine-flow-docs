## Task 1 — Doc Drift Audit

### Finding 1: `FThemes.zinc` documented everywhere, but implementation uses `FTheme.neutral`

> [!CAUTION]
> All three canonical documents and several ADRs describe the theme as `FThemes.zinc` / `FThemes.zinc.dark`. The actual implementation uses `FTheme.neutral.light.touch` / `FTheme.neutral.dark.touch` — a different ForUI API surface.

| Attribute | Detail |
|-----------|--------|
| **Files** | [07-ui-design-system.md](file:///D:/AppDev/mine_flow/Code/mine-flow-docs/architecture/07-ui-design-system.md) §2, §5, §6, Decision Summary rows 2/7; [PRODUCT.md](file:///D:/AppDev/mine_flow/PRODUCT.md) (mirror); [DESIGN.md](file:///D:/AppDev/mine_flow/DESIGN.md) (mirror) |
| **Implementation** | [app.dart](file:///D:/AppDev/mine_flow/Code/mine-flow-app/lib/app/app.dart#L38-L40) uses `FTheme.neutral.dark.touch` / `FTheme.neutral.light.touch` |
| **What's wrong** | STEP-30.6.F3 discovered that forui 0.24.x uses `FTheme.neutral`, not `FThemes.zinc`. The substep notes say "documentation updated" but the architecture doc, PRODUCT.md, and DESIGN.md still all say `FThemes.zinc` throughout. 11+ occurrences of `FThemes.zinc` remain across the three doc files. |
| **Severity** | **Blocking** — An agent or contributor reading the canonical doc would use the wrong API. The STEP-30 substep even records that the doc was updated, but the update was never propagated. |

> [!IMPORTANT]
> The **core blocking issue** is a single root cause: STEP-30.6.F3 corrected the ForUI API from `FThemes.zinc` to `FTheme.neutral` but the documentation update it claims to have done was never actually propagated.
